# Проверка игрового цикла — 26.11.2026

Проверена версия `a9799e3507855706606de6101fede9de1926b791` в Unity 6000.3.8f1 на Windows, Game View 1080×1920. Проверка выполнялась реальными нажатиями мыши в открытом редакторе. Результаты сверены с Editor.log и исходниками. Код и сцены игры не изменены.

## Подтверждённые проблемы

### P1: две тройки в одной строке оцениваются как пять в ряд

На первом уровне при счёте 120 и 7 оставшихся ходах в пятой строке сверху было:

```text
зелёная — коричневая — коричневая — оранжевая — коричневая — оранжевая — оранжевая
```

Обмен четвёртой и пятой фишек дал две самостоятельные тройки разных видов:

```text
зелёная — коричневая — коричневая — коричневая — оранжевая — оранжевая — оранжевая
```

Ожидалось 20 + 20 = 40 очков согласно `ScoreCalculator`, итоговый счёт 160. Получено 150 очков, счёт сразу стал 270, остаток ходов 6, показана победа при цели 200. В журнале только одно начисление: `Score = 270`.

Причина: `Assets/Scripts/Game/MatchTiles/MatchFinder.cs`, `AddLineResults`, строки 100–113. Группировка идёт только по координате строки/столбца. Тип плитки и непрерывность линии не учитываются; любые 5+ плиток в группе получают `FiveInARow`. По коду аналогичный дефект возможен в колонках; отдельный вертикальный пример в этом прогоне не воспроизводился.

Исправление должно выделять отдельные непрерывные линии одинакового типа. Регрессионные случаи: две разные тройки в строке/колонке, тройки через разрыв, настоящие 4/5 в ряд и пересечения.

### P1: открытые уровни не сохраняются между запусками

1. Завершён первый уровень, нажата Menu.
2. Второй уровень стал активным и успешно запустился.
3. Выполнены Stop и Play в Unity.
4. После повторного запуска второй уровень снова серый, нажатие не запускает его; активен только первый.

`Assets/Scripts/Data/GameData.cs:15` каждый раз задаёт `CurrentLevellIndex = 1`. Прогресс остаётся в объекте в памяти; в проверенных игровых скриптах нет сохранения в PlayerPrefs или файл. Проверено именно повторным запуском Play Mode, не отдельным исполняемым файлом.

Если сохранение прогресса пока сознательно отложено для прототипа, это ограничение текущей реализации. Для игры с постоянным прогрессом требуется сохранение после открытия уровня и восстановление при старте.

## Дополнительные наблюдения по исходникам

- В `Assets/Scripts/GameStateMachine/States/RemoveTilesState.cs:12` есть незащищённый `using UnityEditor;` в runtime-коде. Это риск ошибки компиляции standalone-сборки; сборкой в этом прогоне не подтверждалось.
- В `ProjectSettings/EditorBuildSettings.asset` список сцен пуст. Перед сборкой нужно проверить стартовую сцену/профиль сборки. Настройки не менялись.
- В начале Editor.log есть сообщение о закрывающемся IPC-канале редактора. Оно не сопровождалось ошибкой игрового сценария и не классифицировано как баг игры.

## Границы проверки

Не проверены: поражение по исчерпанию ходов, прохождение уровней 2–15 до конца, реальные устройства/касания, звук на слух, долговременная производительность, отсутствие доступных ходов, настоящая комбинация из пяти фишек, сборки Windows/Android/WebGL. Отсутствие ошибок консоли не означает отсутствие логических ошибок.

Автотесты для игры в рамках этой проверки не добавлялись. Ранее изменённый fallback-шрифт остался вне коммита отчёта.
